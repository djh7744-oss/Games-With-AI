# MVP开发边界：先做1%，让1%可玩

## 核心原则

> 完整文档描述的是"最终愿景"。MVP是"用最少的工作验证核心假设"。MVP的目标不是"做出游戏"，而是"验证这个游戏是否值得做下去"。

## 假设列表 (需要原型验证的核心假设)

| # | 假设 | 验证方式 | 失败意味着 |
|---|------|---------|-----------|
| H1 | M&B式四方向战斗在战国背景下"好玩" | 白盒战斗原型 | 整个战斗系统需要重做 |
| H2 | 千人战场可以在RTX3060上跑60FPS | 压力测试 | 必须降规模到500人或砍Mass Entity |
| H3 | "从士兵到帝王"的成长感足够驱动玩家 | 纸面测试→最小成长原型 | 路线设计需要重做 |
| H4 | 经济系统(物价差/贸易)有足够深度 | 纸面模拟→最小贸易原型 | 砍掉复杂经济,只保留简单买卖 |
| H5 | AI国家自主行为让世界"活"起来 | AI模拟(不需图形) | AI退化为脚本触发 |

## Phase 1 MVP: 砍掉90%，只做3件事

### 进入MVP的系统 (3个)

```
✅ 战斗系统 (110): 只有个人战斗+军团战斗基础
   ├── 四方向攻击+格挡 (M&B核心手感)
   ├── 骑马+马上战斗 (核心卖点)
   ├── 100人战场 (不是1000人——先验证手感)
   └── 3种兵种 (步兵/弓兵/骑兵,不是55种)

✅ 角色系统 (120): 只有属性+基础成长
   ├── 六维属性 (统率/武勇/智略/魅力/经营/工艺)
   ├── 1种出身 (游侠或贵族——选一个最容易做的)
   └── 成长: 打怪→属性涨 (简单公式,不搞复杂年龄修正)

✅ 地图: 只有1张战场+1座城
   ├── 2km×2km战场 (平原)
   ├── 1座Lv3城池 (含市集/酒馆/城墙)
   └── 20个敌人 (用于战斗测试)
```

### 不进入MVP的系统 (砍掉)

```
❌ 全部经济系统 → MVP不需要经济, 打怪掉金即可
❌ 全部外交系统 → MVP没有其他国家
❌ 全部内政系统 → MVP没有城池管理
❌ 全部AI系统 (除战场士兵AI) → MVP不需要国家AI
❌ 全部任务系统 → MVP只有"去杀X个敌人"
❌ 全部科技树 → MVP不需要
❌ 全部学派 → MVP不需要
❌ 全部名剑 → MVP只用基础武器
❌ 全部DLC → MVP只有一个场景
❌ 79位历史将领 → MVP只需1个敌人将领
❌ 40+城池 → MVP只需1座城
❌ 48项科技 → MVP只需0项
❌ 10家学派 → MVP只需0家
```

### MVP验收标准 (硬性)

```
□ 可以在平原战场上骑马砍杀20个敌人
□ 四方向攻击的手感"像"骑马与砍杀(不需要完全一样)
□ 100人战场在RTX3060上稳定60FPS
□ 战斗循环: 骑马出城→找到敌人→战斗→回城→基本的"好玩"
□ 可以在城内走动: 酒馆/市集/城墙
□ 整个MVP < 10GB安装包
```

### MVP不做的事 (做了就是浪费)

```
✗ 不要在MVP阶段做任何"好看"的事情
✗ 不要做精细的3D模型 (白盒/商店资产→先验证手感)
✗ 不要做对话系统 (NPC只显示文字即可)
✗ 不要做存档系统 (每次重新开始)
✗ 不要做UI美化 (默认UMG足够)
✗ 不要做音效 (先验证玩法, 音效后期加)
✗ 不要做本地化 (先只做中文)
```

## Phase 2-3: 逐步扩展

### Phase 2: 加入经济+简单AI (MVP验证通过后)

```
新增:
  ✅ 3座城池 (不同物价→验证贸易核心循环)
  ✅ 1个国家AI (秦国→验证"世界不围着玩家转")
  ✅ 1种出身 (第二出身→验证出身差异)
  ✅ 基础任务 (护送/讨伐/寻人——验证任务生成系统)
```

### Phase 3: 加入策略层

```
新增:
  ✅ 战略大地图 (8km×8km最小版)
  ✅ 内政基础 (城池数值+征兵+开发)
  ✅ 外交基础 (宣战/结盟/停战)
```

### Phase 4+: 逐步加入其余系统

```
按优先级:
  1. 科技树 (只有6项基础科技,不是48项)
  2. 学派 (只有3家,不是10家)
  3. 名剑 (只有1-2把,不是10把)
  4. DLC (只有长平之战,不是8个)
```

## 规模对比

| 维度 | 完整文档 | MVP | 削减比例 |
|------|---------|-----|---------|
| 系统数 | 8大系统 | 2系统(战斗+角色) | 75% |
| 兵种 | 55种 | 3种 | 95% |
| 城池 | 40+ | 1(2km²战场+1城) | 97% |
| 兵器 | 47把 | 3把(剑/戟/弓) | 94% |
| 名剑 | 10把 | 0 | 100% |
| 历史将领 | 79位 | 1位(敌将) | 99% |
| 科技 | 69项 | 0 | 100% |
| 学派 | 10家 | 0 | 100% |
| 设计文档 | 180+ | MVP只需参考~15个 | 92% |
| 预计开发 | 3-5年(虚幻) | 3-6个月(可实现) | 90%+ |

## MVP开发流程 (不同于瀑布式)

```
Week 1-2: 搭UE5项目 + 导入白盒场景
Week 3-4: 实现M&B式四方向攻击(参考111_个人战斗系统)
Week 5-6: 加上骑马+马上战斗
Week 7-8: 加上20个敌人(白盒士兵, 无AI, 只会冲)
Week 9-10: 加上100人战场+基础士兵AI
Week 11-12: 加上1座白盒城池(能走进去)
Week 13-14: 战斗循环测试+调整
Week 15-16: 内部试玩→决定: 继续做Phase 2还是砍掉重来

每2周一个可玩的里程碑。
每个里程碑必须"可玩"——不完美没关系, 但要能跑。
```
