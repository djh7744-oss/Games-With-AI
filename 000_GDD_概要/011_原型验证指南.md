# 原型验证指南: 从纸上到引擎

## 核心原则

> 游戏设计是迭代科学。文档里的数字都是假设，只有跑在引擎里的数字才是事实。每个进入开发阶段的系统，必须先在UE5中跑通原型，用实际数据修正文档，而非用文档指导代码。

## 文档→原型的转换标准

### 战斗系统 (最高优先级)

**必须先跑的原型**:
```
1. 伤害公式验证
   在UE5中建一个10m×10m的白盒关卡
   放置玩家角色(武勇50, 持精铁剑伤害42) + 敌人(防御15, HP500)
   实际砍100刀, 记录每次伤害, 验证:
   - 平均DPS是否与公式一致
   - 暴击率(5%+50/200=30%)是否在100刀中≈30次
   - 骑砍速度加成是否真的×2.5(极速)
   
   文档应修改的地方:
   - 如果100刀测完发现DPS比预期低30% → 修正基础伤害公式
   - 如果暴击率偏差>5% → 检查随机数实现
   
2. 格挡手感验证
   用白盒角色测试四方向格挡
   关键问题: "方向匹配格挡是否过于苛刻?"
   找5个人试玩→如果80%的人说"太难" → 放宽格挡判定窗口(从0.2s→0.3s)
   
3. 体力消耗曲线验证
   连续战斗直到体力耗尽→记录时间
   文档说"重击消耗20体力, 体力恢复8/秒"
   实测: 100体力→5次重击耗尽→需12.5秒恢复
   问题: "12.5秒的恢复时间太长还是太短?" → 试玩反馈决定
```

**可以后验证的**:
```
- 士气连锁溃逃概率(需要100+士兵→先不做)
- 水战伤害公式(需要船→先不做)
- 攻城器械伤害(需要城池→先不做)
```

### 经济系统

**不要先做复杂经济!**

```
MVP阶段: 不需要物价表/产业链/货币系统
  只需要: 打怪掉金→金可以在商店买武器
  验证的是: "玩家觉得掉金量合理吗?"

如果打怪掉金之后玩家根本不去商店→经济系统做得再深也没用
如果玩家抱怨"钱不够用"→先调高掉率, 再考虑加入贸易系统
```

### AI系统

```
AI系统的验证不是"AI聪明不聪明"
而是"AI让玩家觉得有趣吗?"

验证方式: 放5个敌人, 打开AI日志
  记录:
  - 敌人平均存活时间
  - 敌人是否主动利用地形
  - 敌人是否在血量低时逃跑
  找3人试玩→问: "敌人感觉像真人吗? 还是像木桩?"
  
AI效用函数的参数(如160文档的0.3/0.15权重)——
不需要验证"公式是否正确", 只需要验证"调整权重后AI行为变化是否合理"
```

## 原型→文档的反向更新流程

```
原型发现 → 记录数据 → 更新文档 → 标记已验证

示例:
  原型发现: 武勇60时实际暴击率是25%, 不是文档写的35%
  记录: doc/ADR/001-combat-crit-rate.md
  更新: 116_士气与伤害模型.md → 暴击公式修正
        225_角色/技能树节点表.csv → 致命一击效果从+10%→+15%
  标记: 文档顶部加标签 [PROTOTYPE_VERIFIED:v0.2]
```

## 不需要验证的文档(标记为"愿景")

以下文档在MVP阶段不需要验证, 标记为 `status: vision`:
- 全部外交系统 (140)
- 全部内政系统 (150, 除基础城池)
- 全部学派任务 (186)
- 全部名剑任务 (184, 除基础武器)
- 全部DLC剧本 (330)
- 全部架空历史 (350)

愿景文档的作用: 当MVP验证通过后, 指导Phase 2+的扩展方向。
但在MVP阶段, 它们只读, 不执行。
